# A-3 allow-list の機械導出結果 (R-05)

作成: 2026-11-09 (第 2 週)。導出スクリプト: `test codes/SourceVault_trusted_allowlist_derive.wls` (ソースを読むだけ。パッケージは読み込まず、ネットワークも FE も使わない)。文面はこの雛形 `test codes/SourceVault_trusted_allowlist_derive_template.md` から埋める。

対象: 02 リスク評価 v1.2 §7.1 A-3 (P0-7「"SourceVault*" の一括信頼を読取・純関数の allow-list に」)。レビュー 07 R-05 の方法に従い、`NBAccess.wl` の `$NBTrustedPackageHeads = <|"SourceVault`" -> {"SourceVault*"}|>` を置き換える allow-list の初期値を、3 条件の積集合として計算した。

**この週は導出と表までとし、`$NBTrustedPackageHeads` の置き換え (A-3 の適用) は所有者が表を見てから行う** (手順は 5 節)。

## 1. 方法

| 条件 | 内容 | 出所 |
|---|---|---|
| (a) 契約 | FunctionContract の `"Effects" -> {}` かつ `"Idempotent" -> True` | `SourceVault_contracts.wl` / `SourceVault_wiring.wl` の登録リテラル (`"Symbol"` と `"Effects"` を持つ Association) を静的に読む |
| (b) privacy 契約 | `SourceVaultRegisterPrivacyContract` の Class が Private か Public (= user-facing で privacy exit を宣言している)。Internal と未宣言は不可 | リテラル呼び出し、`iPDeclareMany` の表、`Scan[... RegisterPrivacyContract[First[#], <\|"Class" -> ..\|>] ...]` の表、`SourceVaultDeclareModulePrivacy` の既定 |
| (c) 走査 | CodeParser の構文木で定義 → 呼出しの有向グラフを作り (`NBAccess_policylint.wl` と同じ方式)、公開関数から sink に推移的に届かないこと。sink = SendMail, URLRead, URLSubmit, URLFetch, URLExecute, URLDownload, URLSave, URLFetchAsynchronous, URLSaveAsynchronous, ServiceExecute, Export, Put, PutAppend, WriteString, WriteLine, BinaryWrite, OpenWrite, OpenAppend, DeleteFile, DeleteDirectory, CopyFile, RenameFile, Run, RunProcess, StartProcess, CreateProcess, KillProcess, SystemOpen, SystemCredential, ExternalEvaluate, Install, LibraryFunctionLoad, CloudDeploy, CloudPut、`$` 付き方針変数 (`$SourceVault*` / `$NB*` / `$Claude*`) への代入 (Module 内・Block 束縛を含む)、動的 dispatch (ToExpression, Symbol, Get, Needs, Uncompress, BinaryDeserialize)、構文木にエラー節点を含む定義 (中身が読めないので「届く」側に倒す) | `SourceVault*.wl` 全部と `NBAccess*.wl` (資格情報 / MAC 層)。他パッケージ (claudecode 等) への弱参照は動的 dispatch として「届く」側に倒す |

走査の保守性: 呼出しは head 位置だけでなく値として現れる記号 (`Map[f, ..]` の f) も辺にし、短い名前で照合する (別 Private 文脈の同名 helper は合流し、到達が増える方向に倒れる)。定義が見つからない公開名 (usage だけ、または動的に定義) は「承認」に倒す。

privacy 契約の Class 語彙 {Private, Public, Internal} には読取 / 書込の軸が無いので、(b) は「user-facing で exit を宣言した関数か」の意味で使い、読取 / 書込の軸は (c) が担う。
